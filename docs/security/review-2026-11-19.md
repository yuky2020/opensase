# Security review — 2026-11-19 (internal, pre-alpha)

Scope: all Go code at commit 9c22d2c. Method: manual review, `go test -race`, fuzzing of
packet/dnsfilter (~21M execs, no panics). Status column is updated as fixes land.

| # | Sev | Finding | Owner | Status |
|---|---|---|---|---|
| 1 | High | An Edge cert can impersonate the Control Plane: shared SANs, and clients do not check the server SPIFFE URI. Leads to attacker snapshot keys being installed via `/v1/pki/ca` | cloud + client | cloud: fixed (distinct SANs per server cert; Edge→CP and opensasectl check the CP URI + PQ in VerifyConnection); client: fixed (pki.ExpectServer on CP, Edge and pinned bootstrap; key refresh only over verified CP, logged) |
| 2 | High | Edge container mounts the whole PKI dir (root CA key, tenant CA keys, snapshot key) and runs as root | cloud | fixed: Edge mounts only `pki/edge` (4 files), cap_drop ALL, runs as uid 1000 via setpriv; CP mounts no Edge keys |
| 3 | High | Tunnel clients reach 169.254.169.254, the Control Plane, Docker/VPC hosts and the Edge host itself (no built-in deny; permissive iptables) | cloud | fixed: Edge built-in deny before policy (`edge`/`builtin-deny`), `-deny-cidrs`/`-allow-private`; iptables FORWARD DROP + wg0 INPUT DNS/ICMP only |
| 4 | High | Device certs expire after 24h with no renewal, so after a day everything fails and PSK rotation silently stops. Edge keeps expired peers | cloud + client | cloud: fixed (`POST /v1/renew`: new key required, atomic serial swap, lost-response retry; Edge removes peers at cert NotAfter); client: fixed (renewal at 50% with new key, atomic device.pem, hot-swap; expired -> status error) |
| 5 | Med | A lost rotation response desyncs the PSK forever (Edge commits epoch N+1 before the client; client retries get 409) | cloud + client | cloud: fixed (Edge accepts epoch = current, re-derived on the new connection, or current+1; older rejected); client: fixed (failed/409/lost rotation -> new epoch-0 session; 3 min handshake liveness check) |
| 6 | Med | DNS filter bypassed via third-party resolvers / DoT / DoH (not forced to the Edge resolver) | cloud | fixed: Edge blocks third-party DNS/DoT and a DoH endpoint list (`edge`/`builtin-dns-bypass`, `-allow-doh`); iptables backup |
| 7 | Med | On-demand peer sync on unknown device certs: amplification against the CP, starving the Edge sync | cloud | fixed: singleflight + 5s minimum interval + 30s negative cache |
| 8 | Med | CP resource exhaustion: no read/write deadlines, unlimited long-polls per device | cloud | fixed: per-route deadlines, ReadTimeout/IdleTimeout, 2 long-polls/device (429), 4096-conn listener limit |
| 9 | Med | Edge identity is global and irrevocable; any edge cert can decide for, and write flows into, any tenant | cloud | fixed: edges registry (`opensasectl edge add/list/revoke`); decide/flows scoped to sessions reported via `POST /v1/edge/sessions` (contract change pending) |
| 10 | Low | Device-controlled flow records and unbounded flow storage | cloud | fixed: times/bytes/strings clamped, 1000 records/min/device, 7-day retention job |
| 11 | Low | Client DNS snooping does not match replies to queries; unsafe when DNSServers is empty | client | fixed (snoop only responses matching txid+qname+client port from the session DNS server; none without DNSServers) |
| 12 | Low | Edge→CP client checks PQ after sending the request | cloud | fixed: PQ + identity checked in VerifyConnection, before any request |
| 13 | Low | Provisioning key passed on the command line (visible in ps / docker inspect) | cloud + client | cloud: fixed (compose secret file `-key-file /run/secrets/provisioning_key`; opensasectl `-token-file`); client: fixed (-key-file, OPENSASE_PROVISIONING_KEY; -key warns) |
| D1 | Design | A user allow rule can override tenant Lockdown and tenant per-app blocks. Decision: tenant Apps and Lockdown are mandatory (see ADR-0012 update) | client (pkg/policy) + cloud (merge) | cloud: fixed (user Apps never override tenant Apps; `TenantApps` filled in the merge); client: fixed (Lockdown drops user allow/ask rules; per-app allow/ask only for firewall.tenantApps) |

Verified correct: PQ-only TLS everywhere through `pqsession.Harden`; PSK derived on the same
connection with a length-prefixed exporter context; chain-shape and role checks in `pki.VerifyPeer`;
constant-time admin token compare; atomic provisioning-key consumption; parameterized SQL;
fail-closed `ask` handling on device, Edge and CP; bounded buffers; 0600/0700 state files.
